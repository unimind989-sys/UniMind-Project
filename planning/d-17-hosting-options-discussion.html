Where should UniMind run, and should we use n8n?

A simple explanation for Ahmed and Ziad. The short answer is that n8n can help with small automation tasks, but it should not be UniMind's main worker, queue authority, or source-processing engine.

Prepared: 24 August 2026 Scope: Phase 1 hosting and D-17 Priority: external hosting at preferably $0

The answer in one minute

n8n is a conductor
It is good at telling other systems when to act. It is not the best place to perform heavy PDF, OCR, audio, embedding, or AI work.
Hosted n8n costs money
n8n Cloud starts at €20 per month when billed annually. Its free trial is not a permanent zero-budget host.
Free n8n still needs a server
Community Edition is free software, but we must host and maintain it on an external VM. It does not remove the hosting decision.

Recommended direction: keep durable job state in PostgreSQL and run a normal Node.js worker on external compute. Add n8n later only if it makes notifications or simple integrations easier.

What UniMind actually needs

When a student or admin starts work, UniMind must accept the request once and finish it even if a process crashes. It must also prevent duplicate provider charges and preserve audit evidence.

Why n8n should not be the main engine

  1. It does not give us a free external server. n8n Cloud is hosted but paid. Community Edition is free but needs a VM that we operate.
  2. Production scaling adds more infrastructure. n8n queue mode normally needs a main n8n process, worker processes, Redis and PostgreSQL. UniMind already needs PostgreSQL and its own workers, so n8n can duplicate the queue and execution layers.
  3. Heavy source processing is a poor fit. n8n Cloud does not provide the Execute Command node used for native tools. Scaled queue mode also cannot use ordinary filesystem binary storage; n8n's supported S3 external binary storage is an Enterprise feature.
  4. Cloud control is limited. n8n Cloud does not let us configure queue mode, worker count, worker concurrency, execution timeouts, database backend, or custom node availability.
  5. UniMind still needs its own reliability rules. n8n retries do not replace job idempotency, leases, heartbeats, budget reservations, deletion verification, provenance or audit.
  6. It can create two sources of truth. If both n8n and PostgreSQL decide whether a job succeeded, recovery becomes harder. UniMind requires PostgreSQL to be authoritative.
  7. It increases the security surface. n8n would hold credentials, webhooks and execution records. Its own security audit warns about unprotected webhooks, risky nodes, credentials and outdated instances. This is manageable, but only worth accepting when n8n provides clear value.

This does not mean n8n is unreliable or badly designed. It means its main strength—connecting applications through visual workflows—is not UniMind's main technical problem.

Where n8n could help later

  • NotificationsSend an email or team alert when a job fails or needs review.
  • Operational ticketsCreate a task from a safe incident event without source content.
  • Simple schedulesCall a reconciliation endpoint by job ID; PostgreSQL still decides the result.
  • Pass identifiers and status metadata, not private source text.
  • Give n8n narrowly scoped credentials.
  • Make every call safe to repeat.
  • Allow UniMind to keep operating if n8n is unavailable.

External hosting options considered

“Free” can mean a permanent allowance, a temporary trial, or a service that sleeps. These options are not equal.

Option Zero-budget status Simple conclusion
OCI Always Free VM Best candidate Full Node containers and the strongest free compute, but we manage the server and must test idle recovery.
Google Cloud Run/Jobs Strong managed option Scales to zero and supports containers; billing, egress and wake-up design require care.
Netlify Background Functions Light jobs only Easy Next.js hosting and 15-minute tasks, but the free account has a shared 300-credit hard limit.
Trigger.dev Good prototype Managed background tasks with monthly free credits; execution pauses when credit is exhausted.
AWS Lambda + SQS Short jobs Useful free allowances, but 15-minute and ephemeral-compute limits complicate large files.
Northflank Sandbox Phase 1 only Always-on sandbox services, but the vendor says the free tier should not be used for production.
Cloudflare Workers + Queues Dispatcher only Good for small messages and wake-ups; the free Worker CPU limit is too small for source processing.
Supabase Edge Functions Dispatcher only Convenient near the database but limited to 150 seconds, 2 CPU seconds and 256 MB on Free.
Supabase Queues / pgmq Transport only A useful Postgres-native queue, but it does not run worker code and may be unnecessary at first.
Upstash QStash Transport only Delivers HTTP messages but still needs an external worker endpoint.
Inngest Orchestration Good durable workflow features, but introduces another execution model and still needs deployed compute.
Vercel Hobby Web/light jobs Excellent Next.js host, but not a heavy worker and Hobby has personal-use constraints.
Render or Koyeb Free Not suitable Free services sleep, and their free tiers do not provide a dependable background worker.
Railway or Fly.io free offers Trial/tiny credit Not enough permanent free capacity for UniMind's worker.
GitHub Actions CI only Useful for tests and deployments; scheduled work can be delayed or dropped.
Founder computer Rejected Stops when the computer or connection is off and violates the approved architecture.

Part Candidate Reason
Database and Auth Two Supabase Free projects One isolated project for preview and one for beta
Durable queue authority PostgreSQL jobs table No extra vendor; matches UniMind's approved state model
Preview worker OCI A1 VM, 1 OCPU / 6 GB Full Node.js container with useful memory at $0
Beta worker Separate OCI A1 VM, 1 OCPU / 6 GB Environment isolation and no founder-computer dependency
Web tier OCI AMD micro VMs or a measured free web host Keep worker memory for processing and preserve two environments
n8n Not installed in Phase 1 Add only when a real notification/integration need justifies it

This is a candidate, not a promise that the beta can run at $0. OCI capacity, idle reclamation, ARM64 compatibility, backups, recovery and the frozen 100-student workload must pass before approval.

Questions to settle together

  1. Are both owners willing to maintain external Linux VMs to keep the cash cost near zero?
  2. Can both owners accept that a free host may be interrupted and require automated recovery?
  3. Who will own security updates, alerts, backups and recovery?
  4. What small monthly amount becomes acceptable if the $0 candidate fails the load gate?
  5. Is there a specific notification or integration that already justifies adding n8n?

الخلاصة بالمصري

n8n مش وحش، بس هو أنسب كمنسّق بين خدمات مختلفة، مش كالسيرفر الأساسي اللي هيشغّل معالجة ملفات الـ PDF والصوت والـ OCR والـ AI.

  • n8n Cloud مدفوع، فمش هيحقق هدف ميزانية صفر.
  • النسخة المجانية محتاجة سيرفر خارجي برضه، يعني مشكلة الاستضافة لسه موجودة.
  • علشان n8n يشتغل بشكل قابل للتوسع هنحتاج n8n رئيسي وworkers وRedis وPostgreSQL.
  • UniMind محتاج PostgreSQL يفضل هو المصدر الأساسي لحالة كل job والتكلفة والـ audit.
  • الأفضل نعمل Node.js worker مباشر، ونضيف n8n بعدين لو احتجناه للإشعارات أو ربط خدمات بسيطة.

الاختيار المقترح للنقاش: نجرب OCI Always Free كاستضافة خارجية، من غير الاعتماد على أجهزة أحمد أو زياد، ونوافق عليه نهائيًا بس بعد اختبارات التحمل والاسترجاع وتشغيل الجهازين وهما مقفولين.
