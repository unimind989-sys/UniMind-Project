## Minimum operational set

1. Local shell plus repository-pinned package scripts for implementation, focused checks, and deterministic evidence.
2. Git/Git Credential Manager for repository transport; the existing GitHub connector, corrected to the UniMind owner repository, for structured PR and Actions work.
3. The pinned Supabase CLI after one human-authorized login, with the in-app side browser for dashboard-only operations.
4. The already-authenticated pinned Vercel CLI, with the in-app side browser for UI-only settings.
5. The in-app side browser for all internal browser work, Playwright Test for repeatable E2E, and external Chrome for founder review.

This set adds no third-party MCP and keeps schema, migration, deployment, and test commands in version control. Credentials stay in provider/native credential stores rather than prompts, repository files, command arguments, or browser exports.

## Maintenance and security basis

- GitHub CLI is GitHub's maintained command-line client and supports multiple authenticated accounts plus explicit `gh auth switch --user`. The current installed CLI is useful but unauthenticated; do not create or paste tokens into agent output. See the [GitHub CLI manual](https://cli.github.com/manual/) and [account-switch command](https://cli.github.com/manual/gh_auth_switch).
- Supabase CLI is an official, active dependency; the installed `2.115.0` reported that `2.117.0` is available, but UniMind keeps reviewed exact pins instead of auto-updating. Official login stores the token in native credential storage when available and may fall back to a plaintext user file when it is not, so confirm the Windows storage path before authorization. See the [Supabase CLI reference](https://supabase.com/docs/reference/cli/su).
- Supabase's official hosted MCP supports OAuth, project scoping, read-only mode, and feature groups, and its own security guidance warns about prompt injection and broad production access. Those controls make it a credible future diagnostic option, not a current requirement. See the [Supabase MCP security and configuration guide](https://supabase.com/docs/guides/ai-tools/mcp).
- Vercel CLI is Vercel's maintained operational client and covers deployments, inspection, runtime logs, staged promotion, and rollback. The repository's authenticated exact pin already supplies this path. See the [Vercel CLI reference](https://vercel.com/docs/cli) and [staged deployment/promotion workflow](https://vercel.com/docs/cli/deploying-from-cli).
- The in-app side browser and Chrome connection are OpenAI-bundled Codex capabilities in the current desktop session. Their sessions may expire, so availability and visible account identity must be rechecked rather than cached as permanent truth.

## Verification-efficiency finding

The previous policy could make a small agent-documentation or skill change run four overlapping layers: the skill validator, agent-readiness checks, the isolated handoff rehearsal, and `pnpm verify`. `$finalize` then inherited the same broad requirements. The correction is impact-based check selection:

- map each acceptance criterion and material risk to one check;
- run the cheapest rejecting check first and each broader required gate once on a stable candidate;
- choose skill validation, agent readiness, and handoff rehearsal only when their specific contracts changed;
- reserve local `pnpm verify` for executable/runtime/build/CI inputs or an explicit task contract, while required GitHub CI remains the full merge gate for documentation/skill-only candidates;
- repeat a passing check only after a relevant diff change, failure, or unresolved risk.

This reduces Codex tool/output/context consumption. It does not weaken mandatory security, database, release, or branch-protection gates.

## Revalidation checklist

Before relying on external access, confirm the exact actor, repository/project, environment, and write scope with one read-only call. Do not infer authorization from a tool name or a signed-in page. Keep secrets out of output, and stop before any new credential, OAuth grant, permission expansion, paid resource, or financial liability until the required human action or confirmation is present.
