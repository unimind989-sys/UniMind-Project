# Skill mechanics

The skill-specific branch of [`skill-authoring`](SKILL.md): where skills live, how each agent loads them, the invocation choice, and validation. UniMind uses two coding agents, OpenAI Codex and Claude Code. Both follow the [Agent Skills](https://agentskills.io) `SKILL.md` format.

## One shared source

- `.agents/skills/<name>/SKILL.md` is the only source. Codex reads it directly.
- Claude Code reads only `.claude/skills/<name>/SKILL.md`. Those files are generated by `pnpm skills:sync` (`scripts/agent/sync-skills.ts`). Never edit `.claude/skills` by hand; edit the source and resync.
- The generated copy contains only `SKILL.md`, with relative links rewritten to `.agents/skills/<name>/...`. Supporting files (references, scripts, templates, assets) stay in the source directory, so keep every supporting-file reference a relative Markdown link or path that the sync can rewrite.
- `pnpm lint:agents` fails when a generated copy drifts from its source.

## Frontmatter

Use only portable fields:

- `name`: required, lowercase letters, digits, and hyphens, identical to the directory name.
- `description`: required, at most 1024 characters (aim for under about 400). State what the skill does, when to use it, and when not to. The description is the always-loaded context pointer, so word it with the method in `SKILL.md`.
- `license`, `metadata`, or `allowed-tools` only when the upstream source already carries them.

Do not write agent-specific fields such as `disable-model-invocation` in the source. The sync adds what Claude Code needs.

## Invocation

Each skill is either automatic or manual. The source of truth is `agents/openai.yaml`:

```yaml
policy:
  allow_implicit_invocation: true   # automatic; false for manual
```

- **Automatic** (`true`): either agent may load the skill when a request matches its description. Users can still invoke it explicitly.
- **Manual** (`false`): Codex excludes it from implicit matching, and the sync adds `disable-model-invocation: true` to the Claude Code copy. Users invoke it as `$name` in Codex or `/name` in Claude Code.

Pick automatic only when ordinary requests should trigger the workflow. Make a skill manual when it is deliberate, expensive, or easy to trigger by accident. Every skill has `agents/openai.yaml`; keep any existing `interface` block.

## Composition

To use another skill's material, link its `SKILL.md` or reference file with a relative path and say when to read it. Claude Code may also load an automatic skill by name; Codex reads the linked file. Either way the instruction works. Put genuinely shared material in one plain reference file rather than duplicating it.

## Splitting by invocation

The invocation cut of splitting (the sequence cut lives in `SKILL.md`): split off an automatic skill when it has a distinct leading word that should trigger it on its own, or another skill must reach it. You pay context load for the new always-loaded description, so that independent reach has to be worth it.

## Validation and records

1. `pnpm skills:sync` regenerates `.claude/skills`.
2. `pnpm lint:agents` checks frontmatter, invocation metadata, local links, and sync drift.
3. Add or update the skill's row in `.agents/skills/EVALS.md` (one should-trigger and one should-not-trigger case).
4. Log the change in `.agents/skills/ADAPTATIONS.md`. Update the inventory and source tables in `.agents/skills/README.md` when a skill is added, removed, renamed, or re-pinned.
