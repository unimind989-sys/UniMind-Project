# WP03 refinement audit: design-system consistency and legacy UI remnants

Auditor: Claude Code sub-agent (read-only). Date: 2026-10-18. Base: `main` at `bcab083`.
Authority: `DESIGN.md` (Direction B "Cobalt"), mockup `planning/design/premium-overhaul/direction-b.html`, `docs/agents/frontend.md`.
Method: static read of `src/app/**` (21 CSS files, 8,263 lines; 112 TSX files), the T18–T21 diffs (`git show --stat`), scripted counts (alias tokens, literal colors, off-scale spacing, radii, unused and undefined CSS-module classes). Nothing was built, served or run, so no screen was rendered. Findings that depend on rendering are marked **needs rendered check**.

## Summary

- The Cobalt rebuild (T19–T21) recolored and restructured most screens, but much of the **shared kit underneath is still Open Folio**. `product-ui.tsx` (`Button`, `ProductLink`, `Notice`, `Row`, `Select`) and `product.module.css` keep the old look: secondary buttons filled with `--surface-strong`, hover in `--accent-soft`/`--accent-ink`, notices without icons, and an always-green `.pill`. These primitives still render 34 `Button`, 41 `ProductLink` and 25 `Notice` instances across 16–18 files, including the rebuilt Batch Leader intake and admin resource pages. Each rebuilt role module then wrote its own correct copy (admin `.primaryAction`, student-account `.primary`, collection `.open`, auth `.primaryAction`, workspace `.routeState button`). Two button languages now sit side by side. This is the main source of the "subtle" legacy feel.
- **Language switch (founder-reported) is confirmed legacy.** The product-shell `LanguageSwitch` is byte-identical to the pre-Cobalt component (`git show 81c624b:src/app/_components/frontend-controls.tsx`). Only its colors changed. It shows two full-word segments with a 14px check icon, and its 50px height makes the 64px Night top bar 70px tall. The mockup draws a compact ringed round `ع` control instead. Three separate switch implementations exist (shell, access pages, landing) with different semantics, and none of them gets Noto Sans Arabic for the `العربية` label in an English page.
- **Legacy tokens are still consumed:** 97 references to Open Folio alias variables across 12 CSS files. `--accent-ink` (`#2456cc`/`#9fbcff`) is not a DESIGN.md token, yet it is used 32 times, including in the T21 admin and Batch Leader modules, for "small blue text" that should be `--action`. One test (`tests/e2e/support/layout-matrix.ts:167-173`) even asserts that the `--accent-soft` alias exists.
- **DESIGN.md components with no shared implementation:** `SegmentedControl` (7 copies), `Notice`/`Status` (6 copies, none with icons except `StatePill`), `PageState` (7 variants, some bare `h1`/`p`/raw `<a>`), and a phone sheet (`--float-up` is defined but never used). The Night band is re-implemented 4 times, each tied to AppShell padding by `-40px`/`-24px` magic numbers.
- **Confirmed visible defects:** the profile avatar puts small white text on `--cobalt` (≈4.1:1 light, ≈3.1:1 dark, fails AA). Materials' "Inactive" status renders in success green. Icons render at 14/18/22/28px instead of 16/20/24. The bottom bar uses 22px icons. Metadata appears as middle-dot strings in about 14 product places. Dead legacy CSS remains (19 unused classes in `product.module.css`, an unused `ActiveAuthShelf`, and a stale Open Folio "direction contract" `<template>` shipped in every page).
- The T19–T21 approvals were delegated overseer approvals ("not a founder review", per the task records). That is consistent with the founder now finding remnants.

Counts: 34 findings (DS-01…DS-34). P0: 0. P1: 4. P2: 15. P3: 15.

### 1.2 Recommended shared primitive: `LanguageSwitch`

**Location:** `src/app/_components/language-switch.tsx` + `language-switch.module.css`. Remove the copies in `frontend-controls.tsx`, `auth-shell.tsx` and `landing.tsx`.

```ts
type LanguageSwitchProps = {
  locale: Locale;                         // current interface locale
  variant?: "segmented" | "link";         // segmented (default): shell + access pages; link: landing's single text link
  tone?: "night" | "paper";               // night (default) for every current call site; paper for a future Settings/onboarding placement
  labels?: "short" | "full";              // short: "EN" / "ع" (shell); full: "English" / "العربية" (access pages, landing)
  hrefFor?: (target: Locale) => string;   // link mode (server-renderable pages); omitted → client button mode
  groupLabel?: string;                    // default "Interface language" / "لغة الواجهة"
};
```

**Visual (night, segmented):** track `--night-2`, 4px padding (on the spacing scale), 12px radius (`--radius-control`). Two segments, each with a ≥44×44px hit area; the visible chip may be 36px, extended to 44px by padding or a pseudo-element, as DESIGN.md:154 allows. Segment radius 9px, 13px/600, current on `--seg-on`/`--seg-on-ink` at 800. **No check icon**: current state is shown by the fill plus `aria-pressed`, and DESIGN calls for a visible state, not a glyph. Hover `--on-night`. Focus uses the global 2px `--cobalt` ring with 2px offset. Fixed order EN | ع (`dir="ltr"`) in both directions. Total about 4+44+2+44+4 = 98px wide and 44px tall (or 52px with the 4px track padding), so the 64px bar holds. The Arabic label sets `lang="ar"` and an explicit `font-family: var(--font-unimind-arabic)` (or the DS-03 `:lang(ar)` rule). The English label gets `lang="en"`.
**Visual (paper):** track `--surface-2` with a 1px inset `--line` ring; current segment `--surface` with a 1.5px `--action` ring. This is the `ChoiceGroup` look without its grey drop shadow (DS-13).
**Visual (link):** today's landing text link, with the DS-03 font fix.

**Semantics:**
- Client mode (product shell): `<div role="group" aria-label>` with two native `<button type="button" lang aria-pressed>`. Accessible names stay the full names ("English", "العربية") through `aria-label` when `labels="short"`. The visible text is a prefix of the name ("EN"⊂"English", "ع" begins "العربية"), so WCAG 2.5.3 label-in-name holds, and the ~20 existing spec locators keep working. This follows DESIGN.md:172 ("native buttons, an accessible name and a visible current state").
- Link mode (access pages, landing): `<nav aria-label>` with `ProductNavigationLink`s carrying `hrefLang`, `lang` and `aria-current="true"` (not `"page"`, since it is the same page in another language), plus `replace` and `scroll={false}`.

**Behavior (both modes):**
1. Build the target as `pathname` + current query with `lang=<target>` + `window.location.hash`, read at click time. Link mode builds the base href on the server through `hrefFor` and appends the hash on click.
2. Navigate with `useProductRouter().replace(target, {scroll:false})` so the synthetic runtime keeps document-local state. Do nothing when target equals current.
3. Preserve drafts and selection: never key any subtree by locale. After the re-render, if focus was lost, move it back to the newly pressed segment. Add one e2e test that types a Chat draft, picks an onboarding answer and opens a fragment, switches language, and asserts all three survive (DESIGN.md:172, 186).
4. Add a `localizedHref(href, locale)` helper. Use it inside `ProductLink`, AppShell nav, `Brand`, `AdminWorkspace` and the other ~58 hand-built `?lang=` sites, so the switch does not depend on every author remembering the parameter (DS-28).

**Founder decision needed (material UI change, needs `Approved commit:`):**
- Option 1 (recommended): the compact segmented "EN | ع" control above. It satisfies DESIGN.md's text ("native buttons", "visible current state", "compact") and matches the access-page segmented switch, so one look covers both.
- Option 2: the mockup-literal single round ringed button showing only the target (`ع` in English, `EN` in Arabic), `aria-label` = target name. It is smaller and pixel-faithful, but the current state is only implicit. That conflicts with DESIGN.md's "visible current state" wording and would need that sentence changed.

**Call sites to migrate:**
- `src/app/_components/app-shell.tsx:13-16` (import) and `:275` → `<LanguageSwitch locale={locale} labels="short" />`
- `src/app/_components/frontend-controls.tsx:115-152` (delete) and `frontend-system.tsx:11` (drop the re-export)
- `src/app/_components/frontend-system.module.css:193-238, 314-316` (delete `.language*`)
- `src/app/(auth)/_components/auth-shell.tsx:29-42` → `<LanguageSwitch locale hrefFor={(l) => languageHref[l]} labels="full" />`; delete `auth.module.css:20-46, 417-420, 443`; href producers `auth-page.tsx:54-63` (add fragment handling and keep the other query) and `product-auth.tsx:249-253`
- `src/app/_components/landing.tsx:47-53` → `<LanguageSwitch variant="link" locale hrefFor={(l) => "/?lang=" + l} />`; delete `landing.module.css:80-94` (`.language`)
- Synthetic screens inherit through `AppShell`, `AuthShell` and `Landing` (`_synthetic/screen-frame.tsx`, `screens/*.tsx`); no direct call sites
- Tests: `tests/e2e/demo/rtl.spec.ts:474-534`, `tests/e2e/support/layout-matrix.ts:141-173` (drop the check-icon and `--accent-soft` assertions; add bar height ≤64px and the draft-preservation test); spot-check `tests/e2e/auth-flows.spec.ts:35` (link name)
